# Changelog

All notable changes to ai-project-starter are documented here.
The format follows Keep a Changelog, and this project adheres to Semantic Versioning.

## [Unreleased]
### Added
- `creation-date` / `created-by` in skill frontmatter (format-checked when present) and `Creation date` in the agent CONFIGS block, stamped by `scripts/skills.mjs new` and `agent-team.sh new` so the format never drifts. "Last usage" is derived, not stored: a `PostToolUse` hook (`log-skill-use.sh`), and `agent-team.sh claim` append to the local git-ignored `.agents/log/usage.jsonl`, and `list` and ai-dash read the latest entry — no commit or merge conflict behind every use.
- `scripts/skills.mjs` (`list` / `check`): zero-dependency skill lister and frontmatter validator — `name` required, lowercase-hyphen and equal to its folder, `description` required and ≤1024 chars, plus YAML pitfalls (unquoted `: `/` #`, unclosed quotes, tabs, duplicate keys); warns when a description doesn't say when to use the skill. Run by `scripts/gate.sh` (new "skills frontmatter" step) and `ai-project-starter doctor`, so a malformed skill blocks the commit instead of silently never triggering.
- ai-dash **Skills** viewer (book icon, local server only): name, description and validity of every skill, with filter and expandable descriptions, via `GET /api/skills` (no skill bodies). Static hosting shows the equivalent commands.
- Automatic execution logging: `scripts/gate.sh` now calls `ai-log.mjs` and `ai-report.mjs` itself at the end of every run (pass or fail), so `ai-dash/data.json` is always current without any agent having to remember a manual step. Never affects the gate's own pass/fail result (best-effort, errors swallowed).
- `AILOG_*` environment-variable convention (`AILOG_TASK_TYPE`, `AILOG_AGENT`, `AILOG_MODEL`, `AILOG_SIZE`, `AILOG_TOKENS_IN`, `AILOG_TOKENS_OUT`, `AILOG_CACHE_READ`, `AILOG_CACHE_WRITE`, `AILOG_TOOL_CALLS`, `AILOG_DURATION`, `AILOG_PR`, `AILOG_OUTCOME`) so an agent can export richer data before running the gate instead of calling `ai-log.mjs` separately; `ai-log.mjs` accepts the same fields as flags too, flag wins over env var.
- `gate_first_try` is now tracked automatically per branch, under `.agents/state/gate-attempts/`: a fail increments the counter, a pass resets it, and the log records whether *this* run was a clean first pass.
- `.agents/README.md`: explains what actually lives in `.agents/` (worktrees, locks, the raw log, local state) and that it is deliberately separate from `docs/agents/`, which holds the committed agent roster.
- `ai-dash/index.html`: animated loading indicator ([thinking-orbs-universal](https://libraries.dev/orbs), loaded from jsDelivr via `import()`, no bundler) replaces the plain "loading…" text while `data.json` fetches and the "no data yet" empty state; degrades to text if the CDN is unreachable.
- `cli/`: zero-dependency Node CLI (`init`, `update`, `adopt`, `doctor`) wrapping `template/`. `init` needs only `git` and `node` — no `bash` — so it works the same on Windows as `init-project.sh` doesn't. `update` pulls starter improvements into an already-created project via a manifest-tracked, content-hash three-way diff: a file only changes automatically when the project never touched it since the last sync; anything else is left alone with `<file>.incoming` written for manual review. `AGENTS.md`, `AGENT_TEAM.md`, `VERSION`, `CHANGELOG.md`, `docs/model-prices.json` and `docs/agents/**` are never auto-applied. Not published to npm yet (`npx github:olavomello/ai-project-starter#main <command>` works without publishing).
- Architecture Decision Records: `docs/adr/template.md` (Title/Status/Context/Decision/Consequences, Michael Nygard's format) and `docs/adr/0001-record-architecture-decisions.md`, the first ADR. `scripts/adr.mjs` (Node, dependency-free) creates, lists, links and supersedes ADRs, following the numbering and file-naming conventions of [npryce/adr-tools](https://github.com/npryce/adr-tools): `new "<title>"`, `new "<title>" --supersedes <NNNN>` (cross-links both files), `list`, `toc [--write]`.
- AGENTS.md §2: agents must write an ADR before or alongside any change that affects the overall architecture (new external dependency, changed data model, new service/integration boundary, changed deployment model).
- AGENTS.md §2: global attribution rule — never mention Claude, an AI assistant, or any tool name in code, comments, commit messages, PR descriptions, or ADRs.
- `ai-project-starter init` guided setup: when run in a terminal, asks for `AGENTS.md` section 0 (name, purpose, stack, administrator, the five knobs) and writes the answers in before the first commit, so a project created interactively is ready to work on immediately instead of needing a manual edit afterward. Skipped automatically outside a TTY (CI, piped input) or explicitly with `--no-prompt`. New `cli/src/lib/prompt.js` and `cli/src/setup.js`; the manifest baseline is hashed after the guided setup runs, so `update` diffs from what's actually committed.
- `PROMPTS.md`: a root-level, maintained library of copy-pasteable prompts for bootstrapping and working on a project via an agent instead of the CLI or `init-project.sh`. Starts with a bootstrap prompt that mirrors `ai-project-starter init`'s guided setup — clone the template, ask the section 0 questions, fill in `AGENTS.md`, init git, commit. Grows alongside the framework; parallel to `cli/` at the repo root, not shipped into `template/`.
- `.claude/settings.json` and two `PreToolUse` hooks ([ADR 0002](template/docs/adr/0002-enforce-project-rules-with-claude-code-hooks-instead-of-convention-only-text.md)): `protect-version.sh` blocks hand-editing `VERSION` or introducing a new release heading in `CHANGELOG.md` through the `Edit`/`Write` tools (the sanctioned release script still works, since it writes through the shell); `block-force-push.sh` blocks any `git push --force`/`-f`. Two rules that were previously convention-only in `AGENTS.md` are now enforced deterministically regardless of model or permission mode.
- `.claude/rules/security.md`: a path-scoped rule (auth, api, routes, middleware, payment, webhook, upload, migrations, `.sql`, `.env*`) that auto-loads `docs/guides/security.md` the moment a matching file is touched, instead of depending on the agent remembering to read it.
- `.mcp.json.example`: scaffolding for projects that want to commit shared, project-scoped MCP server configuration. The starter itself depends on no MCP server; copy to `.mcp.json` and fill in to use.
- `ai-project-starter doctor`: now also validates `.claude/settings.json` as JSON (if present) and checks that every `.claude/hooks/*.sh` is executable. `ai-project-starter init` makes `.claude/hooks/*.sh` executable the same way it already does for `scripts/*.sh`; `init-project.sh` does the same.
- `docs/guides/claude-code.md`: Claude Code–only guide — why `CLAUDE.md` keeps the `@AGENTS.md` import (a `CLAUDE.local.md` would otherwise stop native `AGENTS.md` loading), auto memory vs. committed project memory, skills instead of the legacy `.claude/commands/`, the one bar `.claude/rules/security.md` had to clear to exist, and which settings/MCP files are committed vs. personal. `template/.gitignore` now ignores `CLAUDE.local.md` and `.claude/settings.local.json`.
- `assets/directory-structure.svg`: a dark, file-explorer-style diagram of what a new project gets, with a one-line description per entry, embedded at the top of the README and linked again from "What you get". Generated by `assets/gen-directory-structure.py` (stdlib-only Python) — edit the `TREE` list there and re-run it when the template's top-level layout changes, rather than hand-editing the SVG.
- `mods/starter-hud/`: an optional, off-by-default Claude Code mod that measures real per-turn token, cache and tool-call usage from the engine itself (`turn.step`, `tool.call`, `turn.complete`) and draws a small band above the prompt (task size/budget, cache ratio, last gate result, live agent count), plus a tool-call count on the spinner. Hands the measured numbers to `ai-log.mjs` through a per-branch file (`.agents/state/usage/<branch>.json`), ahead of `AILOG_*` variables but behind an explicit flag. Inert outside a git repository with `scripts/gate.sh`, or on an older Claude Code. Published once, at `mods/starter-hud/`, as a plugin via `.claude-plugin/marketplace.json`, rather than copied into `template/`. Adds a `/budget` command (set or clear a task's token ceiling) that toasts at 80% and can abort the next turn at 100% — advisory only, never blocking an unattended or non-interactive run. See [ADR 0003](template/docs/adr/0003-measure-real-session-usage-with-an-optional-claude-code-mod.md) and `mods/starter-hud/README.md`.
- `scripts/mod.mjs`: the one implementation of turning the session mod on or off, editing `.claude/settings.json`'s `enabledPlugins` key. Shared by the new `ai-project-starter mod` command and the dashboard's Settings area below — never two copies of the same settings-file edit.
- `scripts/ai-dash.mjs`: a `127.0.0.1`-only local server for `ai-dash/` that adds a small Settings area (gear icon, `ai-dash/index.html`) for reading and writing `.claude/settings.json` — today, a live switch for the session mod. Rejects any request whose `Host`/`Origin` isn't local; `ai-dash/index.html` still works as a static file, falling back to showing the toggle command when no server is behind it.
- `ai-project-starter mod <status|enable|disable> [dir]`: wraps `scripts/mod.mjs` from the CLI. `ai-project-starter init` now also asks (interactively, or via `--mod`/`--no-mod` non-interactively) whether to enable the mod, and enables it before the first commit when asked to. `ai-project-starter doctor` reports the mod's current state (informational only — never fails the check over it).
- `AGENTS.md` §0: `Task token budget S / M / L` knob (default `off`), read by the session mod's `/budget` command and by `node scripts/mod.mjs`/`ai-project-starter mod`.
- `PROMPTS.md`: new entry, "Turn the in-session status mod on or off", and the bootstrap prompt now asks the budget and mod questions too (enabling the mod via `node scripts/mod.mjs enable` before the first commit when answered yes).
- `docs/guides/claude-code.md`: new "Session mod (optional)" section — what it is, how to turn it on, and the `/budget` command.
- `docs/guides/efficiency.md` and `docs/guides/security.md`: document the mod's usage-file handoff to `ai-log.mjs`, and the review step (`claude plugin validate <dir>`, read its `hooks:`/`calls:` lines) before installing any mod, this starter's own included.

### Changed
- Dashboard folder renamed `dashboard/` → `ai-dash/` (script, docs and generated `data.json` all moved with it) so it doesn't collide with a `dashboard/` folder a project built on this starter might already have for its own product.
- `scripts/ai-log.mjs` and `scripts/ai-report.mjs` resolve the log and `ai-dash/data.json` against the repo's shared root (`git rev-parse --git-common-dir`) instead of the current working directory, so every git worktree of a project writes to the same files instead of fragmenting the data.
- AGENTS.md section 4, `docs/guides/efficiency.md` and `ai-dash/README.md` updated to describe the automatic logging and the `AILOG_*` convention; the old "every task ends with a manual log line" instruction is gone.
- AGENT_TEAM.md and AGENTS.md section 7 now state explicitly, up front, that agent definitions live in `docs/agents/` and `.agents/` is unrelated runtime state — the split was previously implicit and easy to miss.
- `ai-dash/index.html`: header logo swapped for the same bar-chart glyph as the favicon (was an unrelated gradient dot); "Theme" text button replaced with a sun/moon icon toggle; the "Aggregates only — no prompts, file paths or source content are recorded" footer note removed from the page (the guarantee itself is unchanged and still documented in `ai-dash/README.md` and the root README).

### Fixed
- `npx github:olavomello/ai-project-starter#main <command>` failed with ENOENT: added a root `package.json` exposing `cli/bin.js`. The documented command no longer has a `cli` argument.
- `scripts/mod.mjs` and `scripts/skills.mjs` printed nothing on Windows (the "run as script" check compared `file://${argv[1]}` to `import.meta.url`), so `ai-project-starter doctor`, `mod` and the dashboard toggle could not read their output. Now compared via `pathToFileURL`.
- `ai-project-starter doctor` no longer fails hooks as "not executable" on Windows, which has no execute bit.- `scripts/gate.sh`: the branch name is now sanitized with `printf '%s' "$branch" | tr ...` instead of `echo "$branch" | tr ...` — `echo`'s trailing newline was turning into a trailing underscore (`agent/dev-api-tester` → `agent_dev-api-tester_`), a mismatch against `ai-log.mjs`'s own sanitizing regex that the session mod's usage-file handoff now depends on being identical everywhere.
- `scripts/ai-report.mjs`: `cost()` was pricing the full `tokens_in` value at the uncached input rate on top of separately pricing `cache_read`/`cache_write`, double-charging the cached portion. `tokens_in` is total input (uncached + cache read + cache write); only the uncached remainder (`tokens_in - cache_read - cache_write`) is now priced at the plain input rate.

## [0.1.0] - 2026-09-26
### Added
- `scripts/gate.sh`: single verification entrypoint (format, lint, types, tests, agent team, version gate) with stack auto-detection and `.agents/gate.conf` overrides.
- Engineering baseline in AGENTS.md: commit convention, test policy, security summary, scope limits, project knobs.
- Precedence rule placing AGENTS.md above installed plugins.
- `docs/guides/`: security checklist, efficiency detail, delegation rules — loaded on demand.
- AGENTS.md section 6: external skills (`dataviz`, `frontend-design`, `skill-creator`, `deep-research`) referenced rather than vendored; charts routed through `dataviz`.
- `AGENT_TEAM.md`: charter for agents creating agents — `auto_agents` and `main_merge` flags asked at plan time, spawn tests, depth and concurrency limits, naming convention, lifecycle.
- `scripts/agent-team.sh`: `new`, `list`, `start`, `sync`, `classify`, `finish`, `cleanup`, `claim`, `release`, `check`.
- Worktree-first isolation: every agent works in its own git worktree and finishes with a PR; rebase onto `main` and a passing gate are required before push.
- `agent-team.sh classify`: rates a branch `mechanical` or `administrator` from the diff (sensitive-path list, docs/tests-only rule, 400-line cap), so `main_merge` never depends on an agent's judgement.
- `docs/agents/_TEMPLATE.md` and AGENTS.md section 7.
- README: quick-start walkthrough (create, configure, gate, push, work).

### Changed
- AGENTS.md restructured and kept under ~130 lines; detail moved out to `docs/guides/`.
- `docs/` reorganized: `docs/agents/` holds agent definitions only; `repo-map.md` and `decisions.md` moved to `docs/`.
- CI workflow renamed to `gate.yml` and now runs the full gate instead of the version gate alone.

### Fixed
- `check-version.sh` now reads the version from compact or minified JSON manifests.
- Executable bit restored on all shipped scripts (lost in an earlier upload).
- `scripts/ai-log.mjs` and `scripts/ai-report.mjs` (Node, zero-dependency, cross-platform): append-only execution log and aggregation into `dashboard/data.json`.
- `docs/tasks.md`: fixed task taxonomy — keeps aggregates comparable and keeps client names out of a publishable dashboard.
- `dashboard/`: dependency-free static monitoring page (tokens, cache reuse, gate first-pass rate, cost, per-agent activity) with light/dark themes, hover tooltips and table views; deployable to Vercel with no build step.
- `docs/model-prices.json`: user-filled price table; cost is not shown until it is filled.
- AGENTS.md section 4 now requires a log line per substantial task; `docs/guides/efficiency.md` explains how to read each metric.
- Dashboard redesign: dark-first theme (matches common monitoring-dashboard conventions), stat tiles with inline sparklines and day-over-day deltas, a "recent executions" table, badge-style gate/status indicators.
- `ai-report.mjs` now emits `recent` (last 10 executions — task type, agent, model, gate, tokens; no prompts or paths) for the new table.
- Part-to-whole breakdown switched from a plain bar to a single segmented share bar (donut avoided — deprioritized for part-to-whole per the dataviz skill; a stacked/segmented bar carries the comparison better).
- `dashboard/README.md`: step-by-step for Vercel Deployment Protection (password gate, no code, no database) and a note on IP allowlisting as an additional layer.
- Fixed: a share-bar segment's `class="hit"` was silently overridden by the CSS rule that makes hover-catcher rectangles transparent, hiding the colored strip.
- Fixed: sparkline SVGs had no explicit width, so the generic `svg { width: 100% }` rule expanded them to the flex row's full width and overflowed the tile on narrow screens.
